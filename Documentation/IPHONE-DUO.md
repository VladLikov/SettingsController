Package-тесты и legacy UI проверены на `dd41b98a355a9d4879ba93ec9c47ea9ffbf02278`; последние два коммита меняют только возврат к скрытому списку в sample и диагностическое сообщение UI-теста, код библиотеки идентичен.

## Поведение

В полураскрытом книжном положении Settings занимает левую половину, выбранная настройка либо существующий empty state — правую. На реальном симуляторном устройстве с нативно заданной позой ширина списка по accessibility hierarchy составляет 475,7 из 951 pt (50,02% с округлением); нативный снимок подтверждает совпадение разделителя с книжным сгибом.

Использован `UISplitViewController(style: .doubleColumn)`. Небольшой неинтерактивный UIView читает активные reserved regions типа `.division` в документированном `UIView.updateConstraints()`. Изменение колонок отложено до следующего MainActor turn: запись внутри constraint pass приводила к overlay на холодном tabletop-запуске. При активной division включаются равные доли ширины, снимаются minimum/maximum ограничения колонок и сбрасываются фиксированные ширины. При исчезновении division восстанавливаются исходные значения. Нет проверки имени модели, фиксированных размеров устройства или порога угла шарнира.

Настройка остаётся тем же secondary controller при переходах Partial → Open → Closed → Partial. В закрытом положении открыта выбранная настройка с системным Back. Если настройка не выбрана, при collapse показывается основной список. В раскрытом плоском положении действуют исходные нативные размеры колонок.

В tabletop с горизонтальным сгибом колонки остаются слева/справа, как на iPad, согласно подтверждённому выбору пользователя. Верхняя/нижняя компоновка не реализована; полное избегание горизонтального сгиба не подтверждено. Нативный снимок этого положения включён в доказательства.

## Что дополнительно исправлено

- Empty state центрируется в доступной области правой колонки. Сам scroll viewport по-прежнему проходит до физических краёв view; `.always` применяет системные горизонтальные safe-area insets и при нескроллируемой горизонтальной оси. До исправления часть текста скрывалась за sidebar — это обнаружено на нативном снимке, несмотря на успешные UI-тесты.
- Для expanded Duo не снимается выделение строки только из-за phone idiom.
- Native secondary задаётся через API колонок; повторный navigation wrapper не создаётся для готового UINavigationController.
- Sample корректно находит ещё не материализованную primary колонку. Его отдельные QA launch arguments открывают настоящий экран настроек и выбирают Appearance через штатный маршрут; поза, размеры и layout ими не подменяются.
- UI-тест обновления профиля теперь действительно нажимает Rename и проверяет Updated User.
- Этот усиленный тест обнаружил дефект sample в компактном native split sheet: `popViewController` не возвращал из root secondary к списку. В современном split sample теперь вызывает `show(.primary)` как при collapse, так и при `displayMode == .secondaryOnly`: узкий sheet скрывает primary без collapse. В классическом оставлен прежний pop. Неудачный прогон сохранён рядом с повторной проверкой.

## Совместимость

Новый путь включён при сборке Swift 6.4 / Xcode 27.1 SDK и выполнении на iOS 27.1+. Минимальный compiler/tools для всего пакета — Swift 6.4 (Xcode 27.1+); compiler fallback удалён. На предыдущих runtime сохраняется классическая split presentation. Минимальный deployment target — iOS 15, без изменения signing, зависимостей и публичной конфигурации хоста.

Swift 6.3 больше не поддерживается и не требует отдельной проверки. Установлен Xcode 27.1 / Swift 6.4. Запуск на iOS 15 не выполнен; deployment target не заменяет runtime-проверку.

## Методика и доказательства

Прочитаны установленные skills `iphone-duo-adaptive-layout`, `iphone-duo-hinge-and-scenes`, `iphone-duo-dual-pane-patterns` и `device-interaction`. UIKit API проверены через Context7, официальную документацию Apple и заголовки установленного SDK. Основной инструмент сборки/запуска/UI-тестов — официальный Apple Xcode MCP. Package-тесты запускаются CLI, поскольку импортированная package scheme в sample workspace через MCP возвращала нулевой набор тестов.

Выделенный симулятор: **iPhone Duo Settings QA**, iOS 27.1, `89AED16E-0EE3-47E8-B0A0-1DAAF543672C`. Нативные кнопки Device Hub Closed / Partially Open / Open / Rotate Right управляли настоящей позой; это не эмуляция одной лишь ширины окна.

После успешной установки официальный DeviceInteractionSynthesize сообщал Session not found. После ограниченной проверки использован native CUA для кнопок позы и снимков. Взаимодействие с приложением проверялось XCTest и штатными маршрутами sample. Другие симуляторы и физические телефоны не использовались для этих действий.

Нативные снимки `selected-partial-fixed`, `selected-open-fixed`, `selected-closed-fixed`, `selected-partial-return-fixed`, `selected-partial-rotated-fixed`, `empty-partial-fixed` сняты на коде `4f5f3751f3a3887a601104c46f3fdfff93e2b32e`. Последующие коммиты добавили compiler guard, уточнили тест API колонок и исправили возврат в узком sample sheet; runtime-ветка библиотеки для iOS 27.1 не менялась. Снимки сохранены без ретуши и генерации.

XCTest screenshot API для этого Duo возвращал полностью чёрные изображения 2006×2852. Они не считаются визуальным доказательством; для визуальной проверки использованы настоящие снимки native Device Hub, для геометрии — accessibility hierarchy. Проверка на физическом Duo не выполнена. Итоговый Apple MCP RunAllTests завершился ошибкой XPC без результатов; повторный прогон выполнен CLI на том же устройстве. Ошибка MCP сохранена отдельно и не считается тестовым результатом.

Воспроизведение: открыть sample SettingsExample, выбрать указанный симулятор и Partially Open в Device Hub. Запустить с `-demo-open-settings` для empty state либо дополнительно `-demo-select-appearance` для выбранной настройки. Затем менять позы без перезапуска приложения. Без этих аргументов sample сохраняет обычный пользовательский запуск.
